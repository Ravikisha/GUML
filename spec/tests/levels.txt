Conformance levels. `core` is markup; `app` adds behaviour.

One language, two levels, in the way CommonMark and GFM are one language with two levels. A core
document has no I/O, no state and no behaviour, so a host can render one that arrived from an untrusted
agent — there is nothing in it to run. An app document declares network requests and mutations on the
host's behalf, which is a different thing to accept from a stranger.

Every case here is an **error**, not a filter. A host that asked for core and received an app document
has to be told, rather than handed a page with the fetch silently removed.

:::: markup compiles at the core level
level: core
--- guml
page Landing title="Northwind"
hero
  h1 Build the interface, skip the boilerplate
  p Describe the page, get a deployable build.
section #features cols=3
  card "Ship in minutes" | No boilerplate to review.
  card "Own your output" | Plain framework code you can keep editing.
--- ast
page=Landing title="Northwind"
hero
  h1 content="Build the interface, skip the boilerplate"
  p content="Describe the page, get a deployable build."
section anchor=#features cols=3
  card text="Ship in minutes" content="No boilerplate to review."
  card text="Own your output" content="Plain framework code you can keep editing."
--- diagnostics

:::: raw markup is still allowed at the core level
`raw html` is markup, not behaviour — the same judgement a Markdown renderer makes about inline HTML.
It is still counted as an escape hatch so the rate stays measurable.
level: core
--- guml
page P
raw html
  <hr class="my-4" />
--- html
<hr class="my-4" />

:::: a repeater is not in the core vocabulary
It has nothing to iterate without `data`, so it fails as an unknown tag — enforcement by absence rather
than by a downstream check somebody could forget.
level: core
--- guml
page P
list rows
  text {id}
